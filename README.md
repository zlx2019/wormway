# zora

[中文](README.zh-CN.md)

A programmable network traffic proxy **library**, plus a ready-to-run **application** built on it. Written in Rust: gateway, multi-protocol proxy, reverse tunnels and a web dashboard.

> **Status: pre-release.** zora is developed by a single maintainer. Nothing has been published yet (no crates.io release, no binaries) and everything may change without notice.

## Planned scope

| Pillar | What it covers |
|---|---|
| Gateway | Reverse proxy, forward proxy and load balancing (HTTP/1.1, HTTP/2, gRPC, WebSocket), TLS with ACME, rate limiting, health checks. The L7 engine is based on [Pingora](https://github.com/cloudflare/pingora). |
| Proxy protocols | First batch: SOCKS5, HTTP CONNECT, Shadowsocks, Trojan, VLESS, Hysteria2. More protocols later. |
| Reverse tunnels | Publish services that live behind NAT through the gateway. |
| Dashboard | A web UI and an Admin API for configuration, certificates, users and traffic. |

Deliverables: a set of embeddable crates (`zora-*`) and a single `zora` binary that wires them together. Configuration is a TOML file (`zora.toml`).

Out of scope for now: end-user proxy clients (TUN, system proxy, client-side rule routing).

## Repository layout

| Path | Content |
|---|---|
| `zora-*/` | Library crates, one directory each: `zora-core` (configuration model), `zora-runtime` (listeners, configuration reloads and graceful shutdown) and `zora-control` (SQLite storage with configuration versions, the Admin API, Prometheus metrics and the dashboard). |
| `apps/zora/` | The `zora` binary: `zora run`, `zora check` (validate a configuration file) and `zora schema`. No protocol is built in yet, so `zora run` only accepts configurations without listeners. |
| `ui/` | The dashboard (React and TypeScript). zora serves it under `/ui/` on the Admin API address, `http://127.0.0.1:9872/ui/` by default, and asks for the Admin API token. |
| `zora.example.toml` | Example configuration. |
| `zora.schema.json` | JSON Schema of the configuration file, generated by `zora schema`. Editors use it for completion and validation, for example VS Code with Even Better TOML through the `#:schema` line at the top of the example. |

## Development

Requirements: Rust stable (MSRV 1.98), [cargo-nextest](https://nexte.st/), [cargo-deny](https://github.com/EmbarkStudios/cargo-deny), [typos](https://github.com/crate-ci/typos) and [pre-commit](https://pre-commit.com/).

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo nextest run --workspace
cargo test --workspace --doc
cargo deny check
typos
pre-commit install   # optional: run the checks as Git hooks
```

The dashboard needs Node.js 22.22 or later and pnpm 10. Build it before zora: release builds embed `ui/dist`, debug builds read it from disk, and without it zora serves a page that explains how to build it.

```sh
pnpm --dir ui install
pnpm --dir ui dev     # http://localhost:5173/ui/, API calls go to zora at 127.0.0.1:9872
pnpm --dir ui lint
pnpm --dir ui build   # writes ui/dist
```
